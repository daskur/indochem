# IPLA DATABASE DOCUMENTATION

The normalized database is named `ipla` and uses InnoDB tables, UTF-8MB4 encoding and foreign keys.

## Core Accounts
- `users`: Students and administrators.
- `password_resets`: Hashed, expiring password-reset tokens linked to users.

## Industrial Content
- `processes`: Main production-process records.
- `process_materials`: Raw materials used by a process.
- `process_equipment`: Equipment associated with a process.
- `process_steps`: Ordered manufacturing steps.
- `process_reactions`: Chemical reactions associated with a process or step.
- `process_safety`: Hazard and safety information for a process.
- `process_quality_control`: Quality parameters, ranges and test methods.
- `process_applications`: Industrial uses of a process or product.
- `process_end_products`: Products generated by a process.
- `process_flow_diagrams`: Uploaded or linked process diagrams.
- `equipment`: Reusable equipment records.
- `process_equipment`: Links reusable equipment to industrial processes with process-specific purpose.
- `process_reactions`: Supplies reaction text used by the Chemical Library to discover related published processes; no direct process-to-chemical join table currently exists.
- `chemicals`: Reusable chemical records.

## Learning Content
- `videos`: Process and equipment videos.
- `quizzes`: A quiz associated with a process.
- `quiz_questions`: Questions belonging to a quiz.
- `quiz_answers`: Candidate answers and correct-answer flags.
- `quiz_attempts`: Student score and pass history.
- `user_progress`: Per-process step and completion progress.
- `bookmarks`: User bookmarks keyed by content type and ID.
- `glossary`: Technical terms and definitions.
- `news`: Published educational and industry updates.
- `notifications`: User-facing notifications.
- `certificates`: Process completion certificate records.

## SIWES
- `siwes_logbooks`: Student internship daily records.
- `siwes_reports`: Student internship reports and submission status.

## Relationships
```text
users
  |-- processes.created_by
  |-- user_progress
  |-- quiz_attempts
  |-- bookmarks
  |-- news.author_id
  |-- notifications
  |-- siwes_logbooks
  |-- siwes_reports
  |-- certificates

processes
  |-- process_materials
  |-- process_equipment -> equipment
  |-- process_steps -> process_reactions
  |-- process_safety
  |-- process_quality_control
  |-- process_applications
  |-- process_end_products
  |-- process_flow_diagrams
  |-- videos
  |-- quizzes -> quiz_questions -> quiz_answers
```

Cascade deletes are used for learning details owned directly by a parent process. Content references such as equipment videos and news authors use `SET NULL` where the related object may be removed independently.

## Password reset migration
For an existing database, apply `database/migrations/20261111_create_password_resets.sql` once. New databases created from `database/schema.sql` already include the table.

## Password reset email setup
Password reset links are delivered with PHP's `mail()` function. Configure an outbound mail relay in the web server's PHP configuration before relying on password resets. Set `IPLA_MAIL_FROM` to a valid sender address and `IPLA_PUBLIC_URL` to the canonical application URL, including its subdirectory if applicable (for example, `https://example.com/leaning-production`). Restart Apache after changing its environment or PHP configuration. Local XAMPP installations commonly need an SMTP/sendmail relay configured first.

The request page intentionally shows the same confirmation for existing and unknown email addresses. If delivery fails, the application records a server-side error and invalidates the undelivered token.
